# Snaply — Release & Code Signing Guide

This document covers how to create a signed production release of Snaply.

---

## 1. Prerequisites

- GitHub repository: `https://github.com/DulinNethmira/snaply`
- Rust toolchain installed (`rustup`)
- Node.js 20+ installed
- Tauri CLI: `npm install -g @tauri-apps/cli`

---

## 2. Updater Key Pair

Tauri's auto-updater requires a signing key pair. The **public key** goes in `tauri.conf.json`. The **private key** is stored as a GitHub Secret and used in CI to sign update packages.

### Generate keys (one-time setup)

```sh
npx tauri signer generate -w snaply-updater.key
```

This produces:
- `snaply-updater.key` — **Private key** (KEEP SECRET. Never commit this.)
- `snaply-updater.key.pub` — **Public key** (safe to embed in source)

### Configure the public key

Copy the public key content from `snaply-updater.key.pub` and paste it into `tauri.conf.json`:

```json
"plugins": {
  "updater": {
    "pubkey": "YOUR_PUBLIC_KEY_CONTENT_HERE"
  }
}
```

### Store the private key in GitHub Secrets

1. Go to `https://github.com/DulinNethmira/snaply/settings/secrets/actions`
2. Create secret `TAURI_SIGNING_PRIVATE_KEY` — paste the **full content** of `snaply-updater.key`
3. Create secret `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — leave empty if no passphrase was used

## 3. Windows Code Signing (Production)

Without a code signing certificate, Windows SmartScreen will show a warning when users first run the installer. This is expected behaviour for unsigned software.

To remove the SmartScreen warning for production releases, you need a valid code signing certificate.

### Certificate Options

| Provider | Certificate Type | Approx. Annual Cost | SmartScreen Trust |
|----------|-----------------|--------------------|--------------------|
| DigiCert | EV Code Signing | ~$500/yr | Immediate trust |
| Sectigo | OV Code Signing | ~$200/yr | Reputation-based (takes time) |
| SignPath.io | OV via Microsoft ID | Free tier available | Reputation-based |

**EV (Extended Validation)** certificates provide immediate SmartScreen reputation. OV certificates require building reputation over time via downloads.

### Configure Signing in GitHub Actions

Once you have a certificate:

1. Export your certificate as a `.pfx` file (with password)
2. Base64-encode it: `certutil -encode cert.pfx cert.b64`
3. Add GitHub Secrets:
   - `WINDOWS_CERTIFICATE` — base64 content of `.pfx`
   - `WINDOWS_CERTIFICATE_PASSWORD` — `.pfx` password
4. Add the signing step to `release.yml` before `tauri build`:

```yaml
- name: Import code signing certificate
  run: |
    $cert = [System.Convert]::FromBase64String("${{ secrets.WINDOWS_CERTIFICATE }}")
    $certPath = Join-Path $env:RUNNER_TEMP "snaply.pfx"
    [System.IO.File]::WriteAllBytes($certPath, $cert)
    Import-PfxCertificate -FilePath $certPath -CertStoreLocation Cert:\CurrentUser\My -Password (ConvertTo-SecureString "${{ secrets.WINDOWS_CERTIFICATE_PASSWORD }}" -AsPlainText -Force)
  shell: powershell

- name: Build Tauri application
  env:
    TAURI_SIGNING_PRIVATE_KEY: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY }}
    TAURI_SIGNING_PRIVATE_KEY_PASSWORD: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY_PASSWORD }}
    WINDOWS_SIGN_TOOL: signtool
  run: npx tauri build
```

## 4. Creating a Release

1. Update `CHANGELOG.md` with the new version's notes
2. Bump the version number in:
   - `apps/desktop/src-tauri/tauri.conf.json` → `"version"`
   - `apps/desktop/src-tauri/Cargo.toml` → `version`
   - `apps/desktop/package.json` → `"version"`
3. Commit and push to `main`
4. Create and push a version tag:

```sh
git tag v0.1.0
git push origin v0.1.0
```

5. GitHub Actions automatically:
   - Validates the build
   - Builds the Windows NSIS installer
   - Signs the update package
   - Publishes the GitHub Release with the installer and `latest.json`

---

## 5. Update Manifest Format

The `latest.json` file is automatically generated by the release workflow. It looks like:

```json
{
  "version": "v0.2.0",
  "notes": "See release page for details",
  "pub_date": "2026-09-01T00:00:00Z",
  "platforms": {
    "windows-x86_64": {
      "signature": "...",
      "url": "https://github.com/DulinNethmira/snaply/releases/download/v0.2.0/Snaply_0.2.0_x64-setup.exe"
    }
  }
}
```

## 6. Release Channels

Snaply is structured for multiple release channels:

| Channel | Tag Pattern | Use |
|---------|------------|-----|
| Stable  | `v*.*.*`   | Production releases |
| Beta    | `v*.*.*-beta.*` | Pre-release testing (future) |

To add a beta channel: add a second workflow `beta.yml` triggered by `v*.*.*-beta.*` tags with `prerelease: true` in the GitHub Release step.
